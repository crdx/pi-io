## Package layout

Monorepo with four packages under `packages/`:

| Package        | Description                           |
|----------------|---------------------------------------|
| `tui`          | TUI components (terminal rendering)   |
| `ai`           | Providers, models, streaming          |
| `agent`        | Agent core                            |
| `coding-agent` | Main app, CLI, modes, tools, commands |

Build order follows dependency chain: tui → ai → agent → coding-agent.

## Build

`just build` compiles all packages with tsgo. `just dev` watches with hivemind. `just check` runs biome + typecheck. `just test` runs all test suites (it depends on `build`, see below).

## Testing

`just test` builds first, deliberately. Two different resolution paths are in play:

- Unit tests resolve `@mariozechner/pi-*` to package **source** via aliases in each `packages/*/vitest.config.ts`. These mirror the `paths` in the root `tsconfig.json` and must be kept in sync when a package or subpath export is added.
- Integration tests (`extensions-*`, `resource-loader`, `stdout-cleanliness`) spawn the built CLI or load fixtures that import the package name at runtime. Node resolves those through `node_modules` → `dist/`, outside vitest's module graph, so they genuinely need a current build.

Without the aliases, unit tests silently run against whatever was last compiled into `dist/`, so source changes appear to pass when they do not. `just check` does not catch this because it typechecks source.

## Model registry

`packages/ai/src/models.generated.ts` is generated by `just generate-models` and filtered to the providers in `KEEP_PROVIDERS` (`packages/ai/scripts/generate-models.ts`).

The `openai-codex` model list in that script is hand-maintained, not fetched from models.dev — new Codex models must be added manually and will never arrive via the daily `update-models.yml` job.

Models may declare `cost.tiers` for request-wide pricing bands (e.g. OpenAI's doubled input rate above the short-context window). `calculateCost` picks the tier with the highest threshold below the request's total input usage.
